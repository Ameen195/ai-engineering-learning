# Day 2: Context Windows and Token Counting

## What I learned

### Context window
- The maximum number of tokens a model can process in one request (input + output)
- Examples: GPT-4-turbo = 128K, GPT-3.5-turbo = 16K, Llama 3 = 8K-128K
- If you exceed this limit, the request fails or gets truncated

### Input vs output tokens
- **Input tokens**: Everything you send (system message, conversation history, your question, tool results)
- **Output tokens**: What the model generates (response text, tool calls, reasoning tokens)
- **Pricing**: Input and output are priced separately (output is usually 2-4x more expensive)
- **Speed**: Input is processed in parallel (fast), output is generated token-by-token (slow)

### How to count tokens correctly
- Use the tokenizer that matches the model you're calling
- For GPT-4/GPT-3.5: `tiktoken.encoding_for_model("gpt-4")`
- Chat messages have overhead (~4 tokens per message for formatting)
- Count BEFORE calling the API to avoid surprises

### The context snowball effect
- Each conversation turn re-sends the entire history
- Turn 1: 200 tokens → Turn 2: 400 tokens → Turn 3: 600 tokens
- By turn 15, you're sending ~3000 input tokens just to ask a new question
- This is why coding agents burn through credits so fast

### Cost estimation
- GPT-4: $10/1M input tokens, $30/1M output tokens
- GPT-3.5-turbo: $0.50/1M input tokens, $1.50/1M output tokens
- GPT-4 is ~20x more expensive than GPT-3.5 for the same prompt
- But GPT-4 has 8x larger context window (128K vs 16K)

### Prompt structure
- System message: Sets behavior, persona, rules
- User messages: What the human says
- Assistant messages: Previous model responses (for conversation history)
- Each message adds overhead tokens

### Key insights for AI engineering
1. **Context grows quadratically in agent loops** - the main cost driver
2. **Always count tokens before API calls** - avoid exceeding limits
3. **Choose the right model** - balance cost vs capability vs context size
4. **Optimize prompts** - shorter system messages, trimmed history = lower costs
5. **Cache when possible** - repeated context can be cached (Day 3 topic)

## Vocabulary
- **Context window**: Maximum tokens a model can process (input + output)
- **Input tokens**: Tokens sent TO the model (prompt, history, tools)
- **Output tokens**: Tokens generated BY the model (response, tool calls)
- **Message overhead**: Extra tokens added for chat message formatting (~4 per message)
- **Context snowball**: The effect where conversation history grows cumulatively
